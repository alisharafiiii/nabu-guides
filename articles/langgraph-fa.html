LangGraph؛ ایجنت کی باید متوقف شود؟

وقتی کار چندمرحله‌ای، حساس یا طولانی است، باید بتوانی ایجنت را متوقف کنی، وضعیتش را نگه داری و بعد با تأیید انسان ادامه بدهی.

LangGraph یک runtime سطح‌پایین برای orchestration ایجنت‌های stateful است. ساده‌تر: مسیر کار دورِ مدل را مشخص می‌کند؛ می‌داند الآن کجای کاریم، کجا باید مکث کنیم و بعد از تأیید چطور ادامه دهیم.

ELI5: مثل یک بازیِ «مسیر را انتخاب کن»

ایجنت یک کودک باهوش است که در هر مرحله می‌پرسد «حالا چی؟». LangGraph نقشهٔ بازی است: اگر جواب ساده بود برو جلو، اگر پول یا دادهٔ حساس در میان بود بایست و از یک بزرگ‌تر بپرس. اگر وسط بازی اینترنت قطع شد، جای بازی را فراموش نمی‌کند.

چرا مهم است؟

یک ایجنت واقعی ممکن است شاخه‌های مختلف داشته باشد، وسط کار fail شود، ساعت‌ها اجرا شود یا approval بخواهد. LangGraph برای این‌ها state، node، edge، checkpoint و interrupt می‌دهد.

مرز مهم: LangGraph فقط تصمیم می‌گیرد workflow کی ادامه پیدا کند. trust anchor نیست. برای کار حساس، سخت‌افزار باید تراکنش decode کند و policy نهایی را enforce کند.

Jargon، خیلی ساده

State

دفترچهٔ مشترک: پیام‌ها، نتیجهٔ ابزارها و وضعیت تأیید.

Node + edge

node یک کار انجام می‌دهد؛ edge می‌گوید مرحلهٔ بعد کجاست.

Checkpoint

سیوِ بازی؛ اگر قطع شد، از همان‌جا ادامه می‌دهد.

Interrupt

توقف عمدی تا انسان یا سیستم مجاز پاسخ دهد.

سه مثال واقعی

Refund در پشتیبانی

زیر ۳۰ دلار و داخل policy؟ ادامه. بیشتر از آن؟ ایجنت متوقف می‌شود و انسان تصمیم می‌گیرد.

ایجنت تحقیق

جست‌وجو و draft را انجام می‌دهد؛ وقتی ادعا high-stakes است، قبل از انتشار به reviewer می‌رسد.

عمل onchain

ایجنت swap پیشنهاد می‌دهد. خارج از محدوده؟ LangGraph مکث می‌کند. سپس سخت‌افزار تراکنش decode شده، limit و allowlist را چک می‌کند؛ مدل امضا نمی‌کند.

کی لازم نیست؟

برای یک prompt و یک API call، نه. وقتی مسیر، حافظه، توقف، بازیابی یا approval مهم است، LangGraph ارزشش را دارد.
