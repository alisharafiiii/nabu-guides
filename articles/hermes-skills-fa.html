Loop Library / Loopy

CATALOG + OPTIONAL SKILL
برای کار تکراری

Loop یعنی «یک‌بار انجام بده، نتیجه رو اندازه بگیر، ازش یاد بگیر و با حد توقف دوباره امتحان کن». Library مجموعهٔ loopهای آماده‌ست؛ Loopy هم Skill اختیاری برای پیدا، ساخت، audit و اجرای loopهای محدود و قابل‌بررسیه.

چرا اضافه‌اش کنم؟

وقتی یک کار رو مرتب تکرار می‌کنی و می‌خوای agent بدونه چطور نتیجه رو بسنجه و کِی متوقف بشه.

کی لازم نیست؟

اگر کار یک‌مرحله‌ایه یا هنوز معیار موفقیت و حد توقف نداری.

برای Hermes اول بدون نصب از Library استفاده کن

Catalog و agent guide رو به Hermes بده و یک loop مشخص انتخاب کن. نصب رسمی Loopy فعلاً برای Codex، Cursor و Claude Code مستند شده؛ برای اون‌ها installer تعاملی اینه:

npx skills add Forward-Future/loopy --skill loopy -g

Loop خوب باید check واقعی، تعداد pass محدود و نقطهٔ برگشت اختیار به آدم داشته باشه.

نسخهٔ پیشنهادی من

اگر امروز Hermes رو نصب کردی، از کل این مقاله فقط یک انتخاب انجام بده. یک هفته باهاش کار کن؛ اگر واقعاً درد رو حل کرد، بعدی رو اضافه کن.

عمومی

Agent-Reach یا youtube-full؛ بسته به اینکه بیشتر از وب تحقیق می‌کنی یا ویدئو.

محتوا

Humanizer، و فقط اگر خروجی رو برای آدم‌ها منتشر می‌کنی.

کدنویسی

فقط یکی از بسته‌های Addy یا Matt، نه هر دو از روز اول.

Minions وقتی معنی پیدا می‌کنه که چند job واقعی داری. OMH، SkillClaw، Browser Harness، Cyber pack و codebase-memory ابزارهای «مشکل مشخص» هستن؛ نصب پیشگیرانه‌شون فقط سطح دسترسی و پیچیدگی رو بالا می‌بره.

این repo رو بررسی کن: [LINK]

قبل از هر تغییر:
1) بگو Skill است، app/CLI است یا MCP.
2) همهٔ فرمان‌ها، فایل‌های مقصد، دسترسی‌ها، API keyها و هزینه‌های احتمالی را فهرست کن.
3) README، install script و SKILL.md را برای دستور مشکوک یا دسترسی بیش‌ازحد بررسی کن.
4) اگر dry-run یا نصب project-local دارد، همان را پیشنهاد بده.
5) تا وقتی من دقیقاً تأیید نکرده‌ام چیزی نصب یا اجرا نکن.

بعد از تأیید فقط همان مورد را نصب کن، یک تست کوچک بگیر و روش حذف یا rollback را هم بده.
