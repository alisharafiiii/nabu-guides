هفت Find Health Samples اضافه کن

برای هر متریک یک block مستقل بذار و فیلتر تاریخ رو روی Start Date is in the last 1 day قرار بده. برای ضربان قلب، Limit رو روی حدود 500 بذار تا Shortcut با صدها نمونه گیر نکنه.

یک Text block بساز

هر بخش با یک تیتر مثل #steps شروع می‌شه و خط بعد، Magic Variable همون Health block قرار می‌گیره. تیترها رو lowercase و ثابت نگه دار تا parser هر روز پیداشون کنه.

فایل رو همیشه روی یک مسیر ذخیره کن

یک Save File بذار، گزینهٔ Ask Where to Save رو خاموش کن، مقصد رو Shortcuts/health/latest.txt انتخاب کن و Overwrite رو روشن بذار.

Automation روزانه بساز

در تب Automation، ساعت 07:00 رو انتخاب کن، اجرای Health Export رو اضافه کن و Run Immediately رو روشن کن. بار اول، دسترسی Health و Files رو خودت تأیید می‌کنی.

دو تله‌ای که احتمالاً می‌بینی

TRAP 01

block جدید خالیه

اگر Find Health Samples رو بلافاصله بعد از block قبلی اضافه کنی، ممکنه خودکار ورودی قبلی رو filter کنه. روی token آبی بزن و Clear Variable رو انتخاب کن تا Find مستقل بشه.

TRAP 02

ذخیره گیر می‌کنه

در Settings → Apps → Shortcuts → Advanced، اشتراک‌گذاری حجم زیاد داده رو فعال کن. Limit ضربان و بازهٔ یک‌روزهٔ همهٔ blockها رو هم دوباره چک کن.

مرحلهٔ ۳: رساندن فایل به مک

iCloud Drive رو روی مک روشن کن

System Settings → Apple Account → iCloud → Drive → Sync this Mac. اگر پوشهٔ Shortcuts رو نمی‌بینی، اول همین رو چک کن.

پوشه رو روی مک نگه دار

در Finder روی پوشهٔ health راست‌کلیک کن و Keep Downloaded رو بزن. وگرنه iCloud ممکنه فقط placeholder نگه داره و Claude فایل واقعی رو پیدا نکنه.

فقط همین پوشه رو به Cowork بده

در Claude Cowork از Add Folder استفاده کن و پوشهٔ health رو انتخاب کن؛ نه کل iCloud Drive یا Home folder. دسترسی کمتر، ریسک کمتر.

مرحلهٔ ۴: چهار فایل pipeline

داخل همان پوشه، Claude چهار فایل اصلی می‌سازه. هر فایل یک مسئولیت داره:

latest.txt

خروجی روزانهٔ آیفون. هر صبح overwrite می‌شه و فقط snapshot فعلی رو نگه می‌داره.

parse_daily.py

تیترها و عددها رو می‌خونه، جمع/میانگین/کمینه/بیشینهٔ لازم رو حساب می‌کنه و فقط یک ردیف برای آن روز می‌سازه.

history.csv

تاریخچهٔ رو‌به‌رشد؛ هر روز یک ردیف. اگر همان تاریخ دوباره پردازش شد باید ردیف قبلی رو update کنه، نه duplicate.

build_dashboard.py

CSV رو می‌خونه و یک dashboard.html قابل‌خواندن با کارت‌های امروز، نمودار روند و یادداشت‌ها می‌سازه.

برای اینکه Claude این فایل‌ها رو با ساختار درست بسازه، این Prompt رو داخل Cowork و با همان پوشهٔ health اجرا کن:

در پوشهٔ متصل‌شدهٔ health یک pipeline محلی بساز.

ورودی latest.txt است. بخش‌ها با این headerها جدا می‌شوند:
#steps #hr #sleep #energy #exercise #hrv #rhr
گاهی header به اولین مقدار می‌چسبد، مثل #hr90؛ این حالت را هم parse کن.

1) parse_daily.py بساز که:
— فایل را فقط بخواند و هرگز پاک نکند.
— برای هر روز یک ردیف بسازد.
— steps، energy و exercise را جمع کند.
— hr را به avg/min/max تبدیل کند.
— hrv و resting hr را خلاصه کند.
— sleep را به ساعت تبدیل کند.
— با upsert در history.csv جلوی duplicate date را بگیرد.
— اگر بخشی خالی بود crash نکند و مقدار خالی ثبت کند.

2) build_dashboard.py بساز که از history.csv یک dashboard.html responsive بسازد:
کارت امروز، روند ۷روزه، نمودار ضربان و قدم‌ها، و بخش هشدارهای wellness.
هیچ کتابخانهٔ خارجی لازم نباشد و داده داخل همان HTML قرار بگیرد.

3) قبل از اجرا، plan و فایل‌هایی که می‌سازی را نشان بده. بعد با یک latest.txt نمونه تست کن و نتیجه را توضیح بده.

خروجی کد رو قبل از اتصال به دادهٔ واقعی تست کن. اگر چند دستگاه در Health قدم ثبت می‌کنن، از Claude بخواه منبع نمونه‌ها و احتمال duplicate شدن رو هم بررسی کنه.

مرحلهٔ ۵: ایجنت روزانه

در Cowork یک Scheduled task بساز. این کار هر روز pipeline رو اجرا می‌کنه، dashboard رو به‌روز می‌کنه و خلاصهٔ صبحگاهی می‌ده.

01Freshness checkفایل جدیدتر از ۲۶ ساعت هست؟
02Parseیک ردیف تازه وارد CSV کن.
03Buildداشبورد رو با تاریخچه بساز.
04Briefفقط تغییرهای مهم رو خلاصه کن.
مک باید روشن بمونه یا نه؟

خود Scheduled task می‌تونه در cloud اجرا بشه؛ اما وقتی کار به پوشهٔ محلی مک نیاز داره، Claude Desktop باید روی همان مک باز و در دسترس باشه. اگر فایل‌ها رو به حساب Claude منتقل کنی، اجرای cloud داستان متفاوتی داره. برای این نسخهٔ ساده، مک و Desktop رو زمان اجرا روشن نگه دار.

یک Scheduled task روزانه برای ساعت 07:35 به وقت محلی بساز.

در هر اجرا:
1) latest.txt را بررسی کن. اگر قدیمی‌تر از 26 ساعت بود، هیچ داده‌ای اضافه نکن و فقط بگو sync انجام نشده.
2) python3 parse_daily.py latest.txt history.csv را اجرا کن.
3) python3 build_dashboard.py latest.txt history.csv dashboard.html را اجرا کن.
4) نتیجه را با همان داشبورد قبلی به‌روزرسانی کن؛ duplicate artifact نساز.
5) یک خلاصهٔ کوتاه فارسی از قدم‌ها، خواب، resting HR و HRV بده.
6) فقط بر اساس ruleهای wellness توافق‌شده flag بده و صریح بگو تشخیص پزشکی نیست.
7) هیچ فایل خامی را حذف، عمومی یا به مقصد دیگری ارسال نکن.

هشدار خوب یعنی «تغییر نسبت به خودت»

یک عدد ثابت برای همه معنی یکسانی نداره. بهتره بعد از چند روز، میانگین ۷روزهٔ خودت baseline بشه و ایجنت فقط تغییرهای واضح رو نشون بده.

نمونهٔ Rule شخصیبرداشت سادهکاری که ایجنت باید بکنه
Resting HR بالاتر از baselineممکنه ریکاوری ضعیف، استرس یا بیماری در راه باشهفقط flag و مقایسه با چند روز قبل؛ نه تشخیص
HRV خیلی پایین‌تر از baselineشاید بدن امروز فشار کمتری بخوادپیشنهاد روز سبک‌تر، با لحن احتمالی
خواب کمتر از هدف شخصیامروز انرژی و تمرکز ممکنه پایین‌تر باشهیادآوری خواب؛ بدون ادعای پزشکی
قدم‌ها زیر هدفتحرک روز پایین بودهیک نوج ساده، نه شرمنده‌کردن کاربر

اعداد دقیق رو با سن، شرایط، داروها و توصیهٔ پزشک خودت تنظیم کن. قانون‌های نمونهٔ Artifact مثل HRV کمتر از ۷۰٪ baseline یا resting HR شش ضربه بالاتر، threshold پزشکی عمومی نیستن.

این قسمت رو رد نکن: دادهٔ سلامت حساسه

این pipeline عمداً داده رو از محیط Health بیرون می‌آره. پس امنیتش بیشتر از اینکه به «هوش» ایجنت بستگی داشته باشه، به مرز دسترسی‌هایی بستگی داره که تو تعیین می‌کنی.

Artifact رو Public نکن

داشبورد واقعی سلامت باید private بمونه. لینک عمومی می‌تونه داده‌های شخصی و الگوی زندگی رو افشا کنه.

فقط خلاصه رو نگه دار

برای روند روزانه معمولاً CSV تجمیع‌شده کافیه. نمونه‌های خام ضربان رو بی‌دلیل وارد dashboard نکن.

پوشهٔ کوچک بده

Claude فقط به health folder دسترسی بگیره. دسترسی کل iCloud یا Documents برای این کار لازم نیست.
